# Bullet Craft — the heart of a resume

A resume lives or dies on its bullets. A weak bullet describes a duty. A strong bullet
proves an outcome. Master two formulas, quantify relentlessly, and front-load impact.

## The two formulas

### XYZ (Google / Laszlo Bock)
> **Accomplished [X], as measured by [Y], by doing [Z].**

- X = the result/impact
- Y = the metric that proves it
- Z = the action/how

Example: *"Cut p95 API latency 820ms → 140ms (X/Y) by adding a Redis read-through cache
and killing N+1 queries (Z)."*

You can reorder to lead with the metric when it's the punch: *"Saved $1.2M/yr by
migrating 340 VMs off VMware to KVM."*

### CAR / STAR (when the story matters)
> **Challenge → Action → Result** (STAR adds "Situation/Task" up front).

Use for interview stories and for bullets where the *problem* is the impressive part:
*"Inherited a 0%-tested 200k-line monolith; introduced contract tests + a CI gate,
reaching 70% coverage and dropping prod incidents 60% in two quarters."*

## Front-load the result
Recruiters read the **first half of the first line**. Put the strongest, most relevant,
most quantified outcome there. Order each role's bullets strongest → weakest. The last
bullet of a role gets the least attention — never bury your best win at the bottom.

## Quantify — and what to do when you "have no numbers"
Real numbers win: **%, $, time, throughput, scale, volume, headcount, rank, NPS, uptime,
error rate, revenue, cost, adoption, latency**. Always reach for one.

No hard metric? Use legitimate proxies — never leave a bare verb:
- **Scale/scope**: "across 8 teams / 40 services / 3 regions / 500+ nodes"
- **Frequency/volume**: "processed 2M events/day", "reviewed ~150 PRs/quarter"
- **Before→after state**: "manual weekly release → automated on-merge"
- **Stakes**: "during a Black-Friday peak of 12k req/s"
- **Breadth**: "first/only", "company-wide", "from 0 to production"
- **Relative**: "2x faster", "halved", "top 5%"

If the user genuinely lacks the number, **ask for it** ("roughly how many users? what
was it before?") rather than inventing one. A specific honest range beats a vague claim.

## Anatomy of a strong bullet
```
[Power verb, past tense] + [what/scope] + [quantified result] + [how/with what]
```
- One idea per bullet. If you used "and" twice, it's two bullets (or cut one).
- ≤ ~2 printed lines. Three-line bullets are usually two bullets hiding.
- Correct tense: **past tense** for past roles, **present tense** for the current role's
  ongoing duties (but past tense for completed wins even in the current role).
- No first-person pronouns ("I", "my"). Start with the verb.
- Parallel grammar within a role — all bullets start with a verb in the same tense.

## Verbs to retire on sight
`Responsible for`, `Helped`, `Worked on`, `Assisted with`, `Tasked with`, `Duties
included`, `Participated in`, `Involved in`, `Successfully` (show it, don't assert it),
`Utilized` (→ "used"). These signal duty, not achievement. Replace with a real action
verb from `action-verbs.md`.

## Before → After

Illustrative structures only. Replace brackets with independently verified facts; never invent metrics.

| Before (duty, vague) | After (impact, quantified) |
|---|---|
| Responsible for the CI/CD pipeline. | Rebuilt CI/CD on GitOps, cutting deploy time 45min → 6min and eliminating manual release toil for 6 teams. |
| Helped improve system performance. | Cut p95 latency 40% (820→490ms) by profiling hot paths and adding read-through caching. |
| Worked on cloud cost optimization. | Reduced [measured cost] by rightsizing [verified scope] and automating [specific process]. |
| Managed a team of engineers. | Led [verified team size]; delivered [product] to [verified users] with [measured reliability]. |
| Used Terraform for infrastructure. | Authored 100+ reusable Terraform modules adopted across 300+ subscriptions, standardizing IaC org-wide. |
| Did security improvements. | Closed 73 high/critical findings and cut mean-time-to-remediate from 21 → 4 days by adding policy-as-code gates to CI. |

## Bullet count per role
- Most recent / most relevant role: 4–6 bullets.
- Mid-career roles: 3–4.
- Older / less relevant (10+ yrs back): 1–2, or a single condensed line — or drop to a
  one-line "Earlier experience" rollup.

## The relevance filter
Before keeping any bullet, ask: *does this move the needle for the **target** role?* A
brilliant win that's irrelevant to the target is clutter. Cut or compress it.
